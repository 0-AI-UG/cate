# Chat panel (T3) e2e tests

Build the app and the runtime bundle, then run the suite:

```sh
npm run build
npm run build:runtime
npm run test:e2e:agent
```

`launchApp({ fakeT3: true })` runs the workspace runtime from a fake install
(`fixtures/electron-app.ts`, `fakeRuntimeInstall`) whose T3 harness is
`fixtures/fake-t3.cjs`. The fake implements the host boundary Cate relies on:
environment discovery, the browser-session bootstrap, the thread shell socket,
thread dispatch, and provider status caches.

## Boundaries

- The suite covers the chat view reaching the harness through the workspace
  partition, a new thread binding to the panel, guest survival, and provider
  status in Cate settings. It is not evidence of compatibility with the real
  T3 router.
- The real, patched T3 server ships only in the runtime tarball. Scenarios
  that need it (provider settings RPC, streaming, approvals, restart and
  resume with a fake Codex app server) are not covered by this suite.
- `multi-client-network.spec.ts` uses the same fake to check that a network
  client's chat view reaches the harness through loopback routing.
